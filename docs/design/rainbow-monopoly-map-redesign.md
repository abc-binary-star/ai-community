# 彩虹大富翁地图视觉重制开发方案

文档状态：待评审  
目标版本：地图体验 V2  
更新时间：2026-08-28  
影响范围：`packages/web/app/activity/hell-board` 前端地图表现层

## 1. 结论

本次不改活动规则、100 格编号、队伍位置和服务端接口，只重做地图几何与视觉场景。

新版建议采用「彩虹书岛探险」主题：将当前 4 条平行横线改成一条贯穿整张地图、包含连续 S 弯、回头弯、环山弯、桥梁和地标节点的单向路线。整体借鉴现代大富翁游戏的空间层次、镜头感和高密度场景氛围，但不复制《大富翁 11》的地图、美术素材、角色或 UI。

核心目标：

- 一眼看上去是一张完整的游戏地图，而不是平行排列的进度条。
- 100 个格子形成至少 16 次明显转向、6 个回头弯，路线横纵方向都充分展开。
- 地图在缩小态有清晰轮廓，在放大态能看到格子材质、功能图标、环境细节和队伍棋子。
- 保留现有拖拽、缩放、跟随、缩略图和格子详情能力，并补齐触控与动画体验。
- 不新增后端迁移，不改变 `position = 1..100` 的业务语义。

## 2. 当前实现评估

### 2.1 为什么当前地图显得简陋

| 问题                | 代码证据                                                                         | 用户感知                                        |
| ------------------- | -------------------------------------------------------------------------------- | ----------------------------------------------- |
| 路线轮廓单调        | `lib/track.ts` 固定为 `25 列 × 4 层`，只有 3 个端部 U 形折返                     | 远看是四条平行横线，不像一张可探索的地图        |
| 格子过小且同质      | `CELL = 26`；缩放低于 `0.9` 时统一显示圆点                                       | 首屏默认 `0.55` 倍时，100 格基本只剩彩色数字点  |
| 缺少真正的 SVG 场景 | `board-map.tsx` 将 `<path>`、`<defs>` 直接放在普通 `<div>` 下，没有 `<svg>` 容器 | 赛道底垫、渐变和虚线可能无法按 SVG 标准稳定渲染 |
| 背景只有点阵纹理    | 地图底色为单色米黄加 `radial-gradient` 点阵                                      | 没有地形、区域、建筑、前后景和光影层次          |
| 彩虹使用过满        | 整条跑道直接使用全程彩虹渐变                                                     | 缺少视觉主次，彩虹反而变成廉价的连续色带        |
| 棋子识别度弱        | `team-token.tsx` 是 14px 左右的双色圆盘                                          | 多队同格时拥挤，缺少立体棋子和移动反馈          |
| 视口初始化写死      | 初始比例和重置比例均为 `0.55`                                                    | 不同屏幕无法自动获得最佳构图                    |
| 触控能力不完整      | 支持单指拖拽、滚轮和按钮缩放，未实现双指缩放                                     | 手机查看大地图费力                              |

### 2.2 可直接复用的部分

- `BoardMap` 的平移、缩放、跟随本队和点击格子交互模型。
- `Tile`、`Team`、`position` 等现有类型和 Zustand 状态。
- `MapTile` 的格子类型语义与 `KIND_META` 配色映射。
- `MiniMap` 的视口框、点击跳转和队伍点位能力。
- `TeamToken` 的队伍颜色、当前队伍高亮和完成态标记。
- 服务端 `/api/activity/hell-board/board` 返回结构，无需修改。

## 3. 目标体验与视觉方向

### 3.1 地图主题：彩虹书岛探险

地图不是纯棋盘，而是一座由阅读主题区域串起来的微缩岛屿。路线从左下角「启程码头」出发，穿过七个主题区域，最终抵达右上方「冠军书塔」。

建议区域：

1. **启程码头（1–14）**：木栈道、路牌、书页帆船，色调为珊瑚红与暖橙。
2. **金色书田（15–28）**：麦田、翻开的巨书、铅笔风车，色调为金黄。
3. **青绿谜林（29–42）**：森林、放大镜、小径和石桥，色调为绿色。
4. **云端书桥（43–56）**：高架桥、云朵、悬浮书页，色调为青色。
5. **蓝墨湖湾（57–70）**：湖水、墨水瓶、弧形湖岸，色调为蓝色。
6. **紫晶夜谷（71–84）**：水晶、灯笼、星光洞口，色调为紫色。
7. **终章山城（85–100）**：盘山路、彩旗、奖杯和冠军书塔，回到暖金色作为终局聚焦。

七区只控制环境与局部点缀，不把整段路面刷成高饱和彩虹。跑道主体统一为奶油白石板或浅木质，彩虹色用于路缘、里程旗、功能格和地标光效，以获得更高级的视觉秩序。

### 3.2 路线轮廓

路线保持单向、线性、无规则分叉，但轮廓应像一条真实山路：

```text
                                              [100 冠军书塔]
                      ╭──────╮           ╭────────╯
              ╭──────╯      ╰────╮  ╭───╯
         ╭────╯                   ╰──╯
         ╰────╮       ╭────────╮
              ╰──╮ ╭──╯        ╰────╮
        ╭────────╯ ╰────╮            ╰──╮
        ╰────╮          ╰──────╮        │
             ╰────────╮        ╰────────╯
 [1 启程码头]─────────╯
```

几何约束：

- 画布建议使用 `1600 × 1000` 的 16:10 世界坐标，路线覆盖至少 75% 宽度和 70% 高度。
- 设计 20–24 个控制点，生成 12–16 段平滑曲线；最终形成不少于 16 次可感知转向和 6 个回头弯。
- 任一连续近直线路段不超过 9 个格子，避免再次形成长平行线。
- 相邻格中心距控制在 54–68 世界像素，转弯处按弧长等距采样，不能按贝塞尔参数直接均分。
- 非相邻路线中心距建议大于 120 像素，给格子、棋子和装饰留出空间。
- 允许 1 处视觉上的桥梁跨越，但通过桥面/桥下遮罩明确前后关系，游戏路线仍是唯一的一条线。
- 起点与终点必须分处地图两端，终点抬高并成为全图最强视觉焦点。

### 3.3 质感规范

采用「2.5D 桌游微缩模型」风格，不上 Three.js：

- **地形**：低饱和草地/沙地分区、柔和噪点、局部等高线和不规则岸线。
- **跑道**：三层描边——深色落地阴影、浅色厚边、主路面；弯道保持圆润。
- **格子**：从圆点升级为略带透视的圆角方砖，顶部高光、底部暗边，功能格有独立图标和色签。
- **地标**：每 14 格设置一个中型地标，25/50/75/100 设置里程碑；地标不能遮挡格子编号。
- **棋子**：圆盘升级为「徽章棋子 + 底座 + 投影」，本队棋子放大 1.15 倍并显示轻微呼吸光圈。
- **光影**：统一左上方光源；避免现有大面积硬黑描边，外轮廓改为深棕灰，阴影分为接触阴影与环境阴影。
- **色彩**：背景低饱和，功能信息高饱和；单屏同时出现的强色不超过 3 种。
- **文字**：缩小态只显示每 5 格的里程编号和特殊格图标；放大态才显示全部编号及短标签。

## 4. 技术方案

### 4.1 渲染架构

继续使用 React + SVG + HTML Overlay，不引入 Canvas、Three.js 或新增大型依赖。

```text
BoardMap（视口与交互）
└── MapWorld（统一世界坐标）
    ├── SVG Scene
    │   ├── defs：渐变、阴影、纹理、clipPath
    │   ├── terrain：岛屿、湖泊、分区色块
    │   ├── track：赛道阴影、底座、路面、路缘
    │   ├── decorations：树木、桥、书本、路牌、地标
    │   └── milestones：起点、25/50/75、终点
    └── HTML Overlay
        ├── MapTile × 100
        ├── TeamToken × N
        └── 可点击/可聚焦交互层
```

选择混合渲染的原因：SVG 适合曲线、遮罩、纹理和缩放；HTML 保留现有按钮语义、焦点管理、Tailwind 样式和详情弹窗，不需要重写无障碍交互。

### 4.2 数据驱动的曲线路线

将 `track.ts` 从固定行列公式改为「控制点 → 平滑曲线 → 弧长采样」：

```ts
type TrackControlPoint = {
  x: number;
  y: number;
  tension?: number;
  zone: "harbor" | "field" | "forest" | "cloud" | "lake" | "crystal" | "finale";
};

type TrackSample = {
  x: number;
  y: number;
  tangent: number;
  normalX: number;
  normalY: number;
  distance: number;
};
```

实现步骤：

1. 人工定义 20–24 个控制点，控制整体构图和关键拐弯。
2. 使用 Catmull–Rom 转三次贝塞尔，生成一条连续且可编辑的 SVG path。
3. 在曲线上建立高精度弧长查找表。
4. 按总弧长的 `0/99 ... 99/99` 等距采样 100 个格子中心。
5. 同时计算切线与法线，供格子朝向、棋子偏移、路缘装饰和同格多队排布使用。
6. `trackPoint(index)` 对外接口保持不变，`MiniMap` 与现有调用方可以平滑迁移。

禁止把 100 个格子的绝对坐标手写在组件中。控制点可以人工调优，但格子点位必须由同一个几何模块生成，确保主地图、缩略图、命中检测和动画完全一致。

### 4.3 格子和棋子布局

格子尺寸建议从 `26` 提升到 42–48 世界像素。每个格子根据路径切线轻微旋转，但文字和功能图标保持正向，避免阅读困难。

同格多队不再使用固定 `right/top` 叠放，改为根据路径法线分列：

- 1–2 队：左右分布。
- 3–4 队：2 × 2 紧凑阵列。
- 5 队以上：只展示本队棋子 + 聚合徽标 `+N`，点击后在气泡层列出全部队伍。

移动时不瞬移。记录上一次位置，沿 `index + progress` 的采样位置播放 500–900ms 分段动画；跨过特殊格时不弹中间详情。开启 `prefers-reduced-motion` 时直接到达终点。

### 4.4 场景资源策略

首选项目内原创 SVG 小组件，控制包体和风格一致性：

- 可程序化绘制：树、云、石头、书页、旗帜、桥墩、路灯、里程牌。
- 需要插画精度的 7 个区域地标可使用原创 WebP/AVIF，单张建议小于 120KB，并保留 2x 清晰度。
- 所有装饰资源进入 `packages/web/public/activity/hell-board/map-v2/`，命名包含区域和用途。
- 不直接提取、描摹或改色使用《大富翁 11》的截图、地图、角色、UI 和音效。
- 装饰图必须设置 `pointer-events: none` 和空 `alt`/`aria-hidden`，不干扰格子操作。

### 4.5 响应式与镜头

- 初始比例改为 `fitScale = min(viewportW / BOARD_W, viewportH / BOARD_H) × 0.94`，去掉硬编码 `0.55`。
- 桌面端首次进入显示完整地图；有本队位置时，1.2 秒后平滑聚焦到本队，用户拖动后暂停自动跟随。
- 移动端默认显示本队前后各 8–12 格，保留缩略图作为全图导航。
- 增加双指缩放和双击聚焦；缩放范围根据 fitScale 动态计算。
- 缩略图在手机端缩至 96px，可折叠；桌面保持 140px。
- HUD 工具条与地图世界分离，缩放时不改变按钮尺寸。

### 4.6 视觉层级和细节等级

按缩放比例分三级渲染，避免信息拥挤和无谓性能消耗：

| 等级 | 比例建议    | 展示内容                                              |
| ---- | ----------- | ----------------------------------------------------- |
| 全景 | `< 0.65`    | 地形、跑道、区域地标、每 5 格编号、特殊格、队伍聚合点 |
| 浏览 | `0.65–1.15` | 全部格子编号、功能图标、主要装饰、独立队伍棋子        |
| 近景 | `> 1.15`    | 格子短标签、材质纹理、棋子名称气泡、次级装饰          |

## 6. 分阶段实施

### 阶段 A：路线原型与几何底座（P0，1–1.5 人日）

- 用控制点完成第一版 100 格蜿蜒路线。
- 实现弧长等距采样、切线/法线、最近格命中。
- 主地图和缩略图共享同一条路径。
- 用真实 `<svg>` 修复赛道渲染结构。
- 只使用线框、编号和临时色块完成评审，不提前精修素材。

验收门槛：路线轮廓确认后再进入美术阶段，避免在错误路线之上反复做装饰。

### 阶段 B：核心棋盘质感（P0，2–3 人日）

- 完成岛屿地形、三层跑道、区域底色和格子立体样式。
- 完成起点、25/50/75 里程碑和终点书塔占位视觉。
- 改造格子 LOD 和特殊格识别。
- 完成自动 fit、桌面/移动端基础适配。

验收门槛：桌面 1440×900 和手机 390×844 首屏都能快速识别路线、当前位置和终点。

### 阶段 C：地标、棋子与动效（P1，2–3 人日）

- 完成 7 个区域地标和环境装饰。
- 完成棋子底座、同格聚合和沿路径移动动画。
- 增加双指缩放、双击聚焦、跟随状态反馈。
- 增加进入地图、到达特殊格和冲线的轻量动效。

验收门槛：不依赖说明文字即可感知不同区域；10 支队伍同时存在时仍能辨认本队。

### 阶段 D：视觉 QA 与性能收尾（P1，1–1.5 人日）

- 完成多分辨率截图对比、触控回归、键盘导航和降低动态效果验证。
- 清理遮挡、文字旋转、贴边、纹理摩尔纹和过度阴影。
- 压缩资源，检查首屏加载和拖拽帧率。
- 灰度开关发布，保留 V1 回退入口一轮。

总预估：6–9 人日；若 7 个区域地标需要单独插画精修，另增加 2–4 个美术人日。

## 7. 验收标准

### 7.1 视觉验收

- 全图至少有 16 次明显转向、6 个回头弯，不能出现超过 9 格的超长直线。
- 100 个格子无重叠、无越界、无不可点击点位，编号顺序连续。
- 七个区域在色调和地标上可辨认，但整图仍属于同一套材质与光源。
- 起点、本队位置、特殊格和终点在全景比例下仍可识别。
- 跑道、地形、地标、棋子至少形成 4 个明确空间层级。
- 不使用任何第三方大富翁游戏的受版权保护素材。

### 7.2 交互验收

- 拖拽、滚轮缩放、按钮缩放、双指缩放、缩略图跳转、回到本队全部可用。
- 点击格子仍打开原有详情弹窗，拖拽结束不会误触格子。
- 队伍位置轮询更新后，跟随开启时镜头和棋子平滑移动；关闭时不抢镜头。
- 键盘可聚焦格子，焦点顺序按 1→100，`Enter/Space` 打开详情。
- `prefers-reduced-motion` 下无持续呼吸、弹跳和路径移动动画。

### 7.3 性能验收

- 地图静止时不持续触发 React 状态更新；只有动画或跟随阶段运行 RAF。
- 桌面中端设备拖拽/缩放目标 55–60 FPS，移动端目标不低于 45 FPS。
- 地图新增静态资源压缩后总量建议不超过 1.2MB，单个地标资源不超过 120KB。
- SVG 节点建议控制在 500 个以内；远景隐藏次级装饰。
- 地图交互不导致活动页接口额外请求，后端协议保持兼容。

## 8. 测试方案

### 8.1 单元测试

- `trackPoint(1)` 与 `trackPoint(100)` 落在预期起终点区域。
- 1–100 所有采样点均在画布安全边距内。
- 相邻点距离偏差不超过目标间距的 ±12%。
- 非相邻格不存在小于安全距离的碰撞；桥梁例外需显式标记。
- `trackIndexAt(trackPoint(i)) === i` 对全部格子成立。
- 切线和法线均为有限数值，转弯处不出现 180° 突变。

### 8.2 组件与视觉测试

- 至少覆盖 390×844、768×1024、1440×900、1920×1080 四种视口。
- 构造 10 队同格、起点 0、终点 100、无本队观战四类状态。
- 验证缩放三级 LOD 的临界点没有文字闪烁或布局跳变。
- 建议增加 Playwright 截图基线；若本迭代不引入 Playwright，至少保留四种视口的人工验收截图。


## 9. 风险与控制

| 风险                 | 影响                   | 控制方式                                                 |
| -------------------- | ---------------------- | -------------------------------------------------------- |
| 拐弯过密导致格子碰撞 | 编号和棋子互相遮挡     | 几何测试 + 安全距离检查；先过线框评审                    |
| 装饰遮挡交互         | 格子难以点击           | 装饰统一禁用 pointer events，交互层置顶                  |
| SVG 滤镜过多         | 移动端掉帧             | 阴影复用少量 filter；远景关闭纹理和小装饰                |
| 彩虹色过度使用       | 仍显廉价、视觉噪声高   | 跑道使用统一材质，彩虹只做区域和状态强调                 |
| 自交路线含义不清     | 玩家误判前进方向       | 尽量不自交；唯一桥梁明确上下层和方向箭头                 |
| 新旧坐标逻辑并存     | 缩略图、点击与棋子错位 | 所有消费者只调用同一个 `track` 几何模块                  |
| 用户已有改动较多     | 合并时误删现有功能     | 重制只触碰地图表现层，按文件逐项迁移，不回退活动业务改动 |

## 10. 建议的实施顺序

1. 先完成 `track.ts` 几何原型和 `track.test.ts`，产出一张只有路线与 100 格编号的评审图。
2. 路线确认后，将 `board-map.tsx` 改为合法 SVG 场景并同步改造 `mini-map.tsx`。
3. 完成立体格子、功能格和棋子排布，确保玩法信息清晰。
4. 再加入七区地形、地标、纹理和光影，逐层控制视觉复杂度。
5. 最后做移动动画、双指缩放、截图回归和性能收尾。

第一开发切片建议只做阶段 A：它能最快验证“是否已经像一张蜿蜒的大富翁地图”，且不会把时间浪费在尚未确定的美术细节上。
