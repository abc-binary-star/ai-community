# 帖子段落想法/批注功能需求文档

文档状态：待评审  
目标版本：V1.0  
更新时间：2026-08-06

## 1. 背景与问题

社区已经上线文字划线能力：登录用户可以在帖子正文的单个内容块内选中文字，保存黄色、绿色或蓝色私有高亮，并进行复制、分享、改色和删除。现有实现已具备段落锚点、选区偏移、选中文字快照和帖子编辑后的文本重定位能力，为进一步增加“对原文发表想法”提供了基础。

目前用户只能在文章底部评论。对于长文，读者读到某一段产生的疑问、补充或共鸣，需要先读完整篇，再到评论区复述上下文。其他读者也难以判断某条评论对应哪段原文，作者无法快速定位反馈，讨论因此脱离原文、启动成本高。

本需求希望把讨论入口前移到阅读现场：用户可以围绕一段或一处选中文字写下想法，其他读者在不打断主阅读流的情况下查看、回复和点赞。该能力内部统一称为“批注”，用户侧统一使用“想法”，避免与帖子底部“评论”混淆。

## 2. 调研结论

本次重点参考飞书文档的协作批注和微信读书的阅读想法。不同客户端版本的具体控件可能调整，以下关注稳定的产品机制，而非逐像素复刻。

| 维度 | 飞书文档 | 微信读书 | 对本产品的启发 |
| --- | --- | --- | --- |
| 核心场景 | 团队围绕文档内容协作、审阅和闭环 | 读者在阅读中记录、分享和发现观点 | 产品是公开社区，应兼顾原文定位和轻社交 |
| 锚定方式 | 评论绑定选中文字或内容块，并在侧边栏呈现 | 划线后可写想法，想法与原文片段/段落关联 | 复用现有单块选区，同时补充整段入口 |
| 创建路径 | 选中内容后评论，或从块级入口发起 | 选中文字后划线、写想法，阅读现场完成 | 在现有选区工具条中增加“写想法”，降低迁移成本 |
| 展示方式 | 原文标记 + 右侧评论线程，当前批注与原文联动 | 原文附近显示想法入口，并可聚合查看他人想法 | 正文常态只显示段落想法数量，打开面板后再强调引用文字，避免满屏高亮 |
| 互动能力 | 回复、@、通知、解决/重开，强调任务闭环 | 公开/私密、点赞、回复、个人笔记沉淀，强调观点传播 | 首版采用公开/私密、回复、点赞；不引入“解决”，避免协作语义错位 |
| 内容管理 | 评论线程可被处理和收起，保留上下文 | 个人可回顾自己的划线和想法 | 首版提供“我的想法”筛选；跨帖子笔记库放到后续版本 |
| 风险控制 | 权限跟随文档协作权限 | 公开内容承担社区治理成本 | 公开想法必须接入举报、拉黑、审核和频控 |

调研后的核心判断是：不能直接照搬飞书的“评论即任务”，也不应照搬微信读书在正文中密集展示他人划线。更适合本产品的形态是“段落级轻入口 + 侧边讨论面板”：正文保持干净，讨论紧贴原文，公开想法形成社区互动，私密想法承担个人记录。

## 3. 产品目标

**用户目标。** 读者在产生观点的当下，能用不超过两步的操作把想法绑定到准确原文；后来的读者能快速理解观点上下文并参与讨论；作者能定位读者对具体段落的疑问和反馈。

**业务目标。** 提升长文的有效互动率和讨论深度，让高质量观点从文章底部回到内容现场，并为后续“热门段落”“作者回应”“个人阅读笔记”等能力积累结构化数据。

**首版不追求。** 不替代帖子底部评论，不做多人审稿任务流，不做批注解决/重开，不做跨段落选区，不做 AI 自动生成想法，不做全站个人知识库。

## 4. 产品原则

1. **原文优先。** 想法入口和数量提示不能显著打断阅读，公开想法不常态覆盖正文背景色。
2. **上下文明确。** 每条想法必须保存引用范围或段落快照，脱离原文后仍能理解其讨论对象。
3. **公开与私密可预期。** 发布前清楚展示可见范围；私密想法不得计入公开数量、榜单或通知他人。
4. **划线与想法相互独立。** 删除个人划线不删除想法，删除想法也不删除个人划线；二者可以关联，但生命周期分离。
5. **复用社区治理。** 公开想法和回复属于用户生成内容，沿用现有举报、拉黑、审核、敏感词和通知偏好。

## 5. 用户与场景

**普通读者。** 阅读时对某句话产生共鸣，选中文字后写公开想法；或希望仅供自己回顾，写私密想法。

**讨论参与者。** 看到段落右侧有想法数量，打开面板阅读观点，对有价值的想法点赞或回复。

**帖子作者。** 查看读者对具体段落的疑问和补充，从引用原文快速定位，并在原位置回应。

**未登录访客。** 可以查看公开想法和回复，进行发布、回复、点赞时触发登录。

## 6. 核心方案

### 6.1 创建入口

**选中文字。** 用户在单个可划线内容块内选中文字后，现有浮动工具条增加“写想法”入口。点击后保留选区，在桌面端打开右侧面板、移动端打开底部抽屉，并自动带入引用文字。现有三色划线、复制、分享入口保持不变。

**整段入口。** 桌面端鼠标移入可批注段落时，在段落右侧显示想法图标；移动端点击段落后，在轻量操作条中显示“写想法”。点击后以整个段落为讨论对象，不要求用户先框选文字。

代码块不支持批注，沿用现有划线限制。标题、正文段落、列表项、引用块支持批注；图片、分隔线和嵌入资源首版不支持。

### 6.2 编辑器与发布

编辑器顶部展示引用内容，过长时最多显示两行并支持展开。正文输入上限 1000 字，去除首尾空白后至少 1 个字符。支持纯文本、换行、@提及；首版不支持图片、附件和富文本。

可见范围提供“公开”和“仅自己可见”两个选项。默认选中公开，并在发布按钮旁持续展示当前范围；系统记住用户最近一次选择，但每次发布前都可修改。公开想法发布后，其他用户可在该段落查看并收到相关互动通知；私密想法仅本人可见，不允许他人回复或点赞。

发布成功后关闭输入态，保留讨论面板并定位到新想法。失败时保留草稿和可见范围，展示可重试错误，不重复创建。

### 6.3 正文提示

有公开想法的段落右侧显示想法图标和数量，数量只统计有效的公开根想法，不统计回复和私密想法。桌面端图标位于正文内容区外侧，不能挤压正文宽度；移动端位于段落末尾的轻量行内位置。数量超过 99 显示“99+”。

正文不常态渲染所有人的选区高亮。用户打开某条想法时，系统临时强调其引用文字；关闭面板后恢复。当前用户自己的私密划线仍按现有颜色显示。若一个段落同时存在划线和想法，点击划线先显示划线菜单，菜单中增加“查看关联想法”；点击段落想法图标直接打开讨论面板。

### 6.4 想法面板

桌面端使用固定右侧面板，建议宽度 360-400 px；移动端使用最高约 85% 视口的底部抽屉。面板头部展示段落引用、公开想法数和关闭按钮。

列表默认按“热门”排序，可切换“最新”。首版热门分采用简单可解释规则：点赞数优先，其次回复数，再按发布时间倒序；不引入复杂推荐模型。当前用户可切换“只看我的”，同时展示本人公开和私密想法，私密条目带清晰锁标识。

每条想法展示作者、发布时间、正文、可见范围（仅本人可见时）、点赞数和回复数。根想法支持一级回复，回复按时间正序展示；首屏默认展开最近 3 条，其余点击后加载。点击引用文字可滚动并临时定位原文。

### 6.5 互动与管理

登录用户可以点赞/取消点赞公开想法，操作需幂等。登录用户可以回复公开想法，回复上限 500 字，支持 @提及。回复仅做一级结构；回复某条回复时，在内容中显示“回复 @用户”，数据仍归属于根想法，避免深层嵌套。

作者可以编辑自己的想法和回复，编辑后显示“已编辑”；可以删除自己的内容。删除根想法时，若无回复则直接从公开列表移除；若已有回复则保留“该想法已删除”占位及回复线程，避免上下文断裂。私密想法删除后立即对本人不可见。

公开想法和回复支持举报。被当前用户拉黑的账号所发布内容默认折叠；命中现有审核规则时按现有评论处置方式处理。帖子作者首版不具备删除他人想法的额外权限，以免形成不透明控评；可举报或交由管理员处置。

### 6.6 通知

以下行为产生通知：有人回复我的公开想法、有人回复我在想法线程中的回复、有人 @我、有人点赞我的公开想法。点赞通知沿用现有聚合策略，避免逐条轰炸。帖子作者默认不接收每一条想法通知，可在后续版本提供“订阅本文想法”；首版仅当作者被回复或 @时通知。

私密想法不产生对外通知。删除或审核下架内容后，相关通知点击应进入帖子并提示“内容已不存在”，不能跳转到空白页面。

### 6.7 原文编辑与锚点失效

创建想法时保存段落锚点、选区起止偏移、选中文字、段落文本快照和帖子内容版本摘要。渲染时优先在原锚点段落内查找选中文字；找不到时仅在全文唯一匹配的情况下迁移。整段想法优先使用段落锚点和段落文本快照匹配。

原文编辑后无法可靠定位的想法标记为“原文已变更”。这类想法不再显示于具体段落侧边，但仍保留在帖子级“本文想法”列表中，并展示创建时的引用快照。作者可以删除自己的失效想法。系统不得静默把想法挂到相似但不确定的段落。

帖子删除后关联想法、回复和点赞按现有级联策略删除；帖子软删除期间不得通过想法接口读取正文或私密数据。

## 7. 信息架构与状态

| 对象 | 状态/分类 | 说明 |
| --- | --- | --- |
| 想法 | public / private | 公开想法所有人可见；私密想法仅作者可见 |
| 锚定范围 | selection / paragraph | 精确选区或整个段落 |
| 锚定状态 | attached / orphaned | 正常挂载或因原文变化失去可靠位置 |
| 内容状态 | active / deleted / moderated | 正常、用户删除、审核下架 |
| 回复 | active / deleted / moderated | 与根想法分开管理，保持线程上下文 |

用户侧名称统一为“想法”“回复”“仅自己可见”；接口和数据模型使用 annotation、annotation_reply，避免与现有 post comment 混用。

## 8. 技术与数据建议

建议新建独立的批注领域模型，不直接复用现有评论表。两者可以复用作者信息、点赞、举报、通知和审核基础能力，但统计口径、锚点字段、私密权限和生命周期不同，强行复用会污染帖子评论数、讨论摘要和搜索结果。

**Annotation 核心字段：** id、post_id、user_id、scope、anchor、start_offset、end_offset、selected_text、paragraph_snapshot、content_digest、body、visibility、anchor_status、status、reply_count、like_count、created_at、updated_at。

**AnnotationReply 核心字段：** id、annotation_id、user_id、reply_to_user_id、body、status、created_at、updated_at。

**建议接口：**

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | /api/posts/:postId/annotations | 获取公开想法、本人私密想法和段落计数，支持 anchor、sort、mine |
| POST | /api/posts/:postId/annotations | 创建选区或段落想法 |
| PATCH | /api/posts/:postId/annotations/:id | 编辑正文或可见范围 |
| DELETE | /api/posts/:postId/annotations/:id | 删除自己的想法 |
| POST | /api/posts/:postId/annotations/:id/replies | 回复公开想法 |
| PATCH/DELETE | /api/annotation-replies/:id | 编辑或删除自己的回复 |
| POST/DELETE | /api/posts/:postId/annotations/:id/like | 点赞或取消点赞 |

列表接口必须在服务端完成可见性过滤，不能把他人私密想法下发后依赖前端隐藏。创建、点赞和回复接口增加用户级频控；所有写操作支持幂等或防重复提交。公开想法进入全文搜索、帖子讨论摘要等下游能力均不属于首版，后续单独评估。

## 9. 版本范围与优先级

### P0：首版上线

- 选中文字和整段两个创建入口
- 公开/仅自己可见想法
- 段落想法数量、桌面侧栏、移动端底部抽屉
- 热门/最新排序、只看我的
- 一级回复、点赞、编辑、删除
- 举报、拉黑折叠、审核、频控
- 回复/@/点赞通知
- 原文变更后的重定位与失效兜底
- 基础埋点和灰度开关

### P1：体验增强

- 个人跨帖子“我的划线与想法”页面
- 帖子作者订阅本文想法、作者标识和精选想法
- 想法草稿自动保存
- 分享单条想法及原文定位链接
- 键盘快捷操作和更完善的无障碍支持

### P2：内容与智能化

- 热门段落、优质想法推荐
- 作者汇总读者疑问
- AI 聚合同段观点或生成讨论摘要
- 批量导出个人阅读笔记

## 10. 数据指标

**核心指标。** 上线后 28 天内，长文阅读用户的有效互动率提升；有效互动定义为创建公开想法、回复想法或点赞想法中的任一行为。重点观察“创建公开想法的阅读用户占比”和“每百次长文阅读产生的有效想法数”。

**过程指标。** 选区工具条曝光到打开编辑器转化率、编辑器打开到发布成功率、公开/私密占比、段落图标点击率、想法阅读到回复/点赞转化率、作者参与率。

**质量与护栏。** 举报率、审核下架率、拉黑触发率、接口失败率、重复创建率、锚点失效率、面板打开耗时、正文布局偏移、帖子阅读完成率。若想法功能导致阅读完成率明显下降，应优先降低正文提示强度，而不是继续增加入口曝光。

## 12. 验收标准

1. 登录用户在单个可批注块内选中文字，可以打开编辑器并成功创建公开或私密想法；跨块选区和代码块不显示入口。
2. 登录用户可以从段落入口创建整段想法；未登录用户点击创建、回复或点赞时进入登录流程，操作完成后可返回原段落。
3. 公开想法对所有可访问帖子的人可见并计入段落数量；私密想法仅作者可见，不计数、不被搜索、不产生对外通知。
4. 段落有多条公开想法时，正文只显示一个聚合数量入口；打开面板后可以在热门、最新和只看我的之间切换，切换不丢失当前段落上下文。
5. 用户可以点赞、取消点赞、回复、编辑和删除自己有权限操作的内容；重复点击或网络重试不产生重复记录。
6. 根想法已有回复后被删除，回复线程仍可阅读且根节点显示删除占位；审核下架内容不泄露原正文。
7. 删除划线不删除关联想法，删除想法不删除划线；两种入口点击区域和菜单行为无冲突。
8. 帖子编辑后，能够可靠匹配的想法迁移到正确段落；无法可靠匹配的想法进入“原文已变更”状态，不错误挂载到其他段落。
9. 举报、拉黑、敏感词、通知偏好与现有评论规则一致；服务端不会向无权限用户返回私密想法数据。
10. 在主流桌面和移动端视口下，段落数量入口、侧栏/抽屉、编辑器和键盘均不遮挡正文核心内容；面板开关不会造成明显页面跳动。

## 13. 风险与待确认项

**公开入口强度。** 默认公开更符合社区场景，但存在用户误发风险。设计稿需保证可见范围始终可见，并通过灰度数据观察公开转私密和删除行为；若误发明显，可改为首次使用时显式选择。

**讨论分流。** 想法可能分走帖子底部评论。首版指标应同时观察总有效互动和底部评论数，不以单一评论增长判断成功；底部评论继续承载整篇观点，段落想法承载局部讨论。

**正文密度。** 热门文章可能每段都有大量想法。正文只显示聚合数量，面板按需加载；后续可增加仅显示热门段落或用户偏好开关。

**存量内容。** 现有划线不自动转为想法。用户点击已有划线时可从菜单进入“写想法”，创建后通过关联 id 建立关系。

**最终需评审确认。** 用户侧名称是否统一为“想法”；可见范围是否默认公开；首版是否必须包含整段入口；热门排序是否接受简单规则；帖子作者是否需要首版订阅本文想法。
