# EPUB 书籍翻译 Agent 应用 - 产品初步雏形方案

## 一、项目概述

### 1.1 项目定位
本项目是一个基于 Agent 架构的 EPUB 书籍翻译系统，用户上传 EPUB 格式的外文书籍，系统自动将其翻译为高质量简体中文版，并保持原有排版格式。核心技术栈采用 Go 语言 + 字节跳动 Eino 框架 + CloudWeGo 微服务生态。

### 1.2 核心目标
- **格式准确**：翻译后 EPUB 结构完整，章节、样式、图片等元素与原书一致
- **翻译质量**：上下文连贯，人名/地名/术语统一，语义准确流畅
- **高性能**：支持并发翻译，充分利用 Go 语言与 Eino 框架的并发能力
- **可观测**：翻译进度实时追踪，错误重试机制完善

### 3.2 核心数据流

1. **上传阶段**：用户上传 EPUB → 保存文件 → 创建 Task 记录（状态=PENDING）
2. **解析阶段**：EPUB Parser 解析元数据、目录、章节 HTML 内容 → 章节级拆分
3. **分块阶段**：按章节/段落/Token 预算将文本切分为可翻译 Chunk
4. **Agent 翻译阶段**（核心 Eino Graph 编排）：
   - 输入 Chunk + 上一段上下文 + 术语表 + 章节摘要
   - TranslateAgent 调用豆包模型翻译
   - QualityReview 自检术语一致性与格式正确性
   - 翻译完成后更新 Chunk 状态，生成段落摘要注入上下文
5. **组装阶段**：翻译结果按 Chunk 顺序合并 → 写回对应 HTML
6. **生成阶段**：所有章节写回 → 重新组装 EPUB → 生成翻译后文件 → Task=COMPLETED

## 四、Agent 架构详细设计（基于 Eino）

### 4.1 Eino 核心组件使用

| Eino 组件 | 在本项目中的用途 |
|-----------|-----------------|
| **ChatModel** | 封装豆包 Doubao-Pro-128K 调用，配置重试/超时/流式 |
| **ChatTemplate** | 翻译 Prompt 模板、审校 Prompt 模板、摘要 Prompt 模板 |
| **Graph 编排** | 翻译流水线的有向图：Translate → Review → (不合格重译) → Output |
| **Lambda** | 文本清洗、HTML 标签保留、术语抽取与对齐 |
| **Callbacks** | 翻译进度回调、Token 用量统计、错误日志埋点 |

### 4.2 翻译上下文管理策略

为解决长篇翻译中上下文连贯问题，采用 **三重上下文叠加机制**：

| 层级 | 策略 | 作用 |
|------|------|------|
| **局部滑动窗口** | 当前 Chunk 前 300 + 后 100 字符原文 | 句子衔接流畅，不出现"断句感" |
| **段落级摘要** | 每翻译完一段由 LLM 生成一句摘要，累积成章节摘要 | 保证人物、情节、逻辑连贯 |
| **术语一致性库** | 翻译前提取专有名词（人名/地名/术语），建立统一术语表 | 人名、地名、专有词汇前后一致 |

### 4.3 Eino Graph 翻译节点设计

```
START → [PreProcess: Lambda 清洗+格式化]
        ↓
      [TranslateNode: ChatModel + TranslatePrompt]
        ↓
      [ReviewBranch: 质量判定分支]
        ├─ 合格 → [PostProcess: Lambda 还原格式] → END
        └─ 不合格(最多重试N次) → [RewritePrompt + TranslateNode]
```

关键设计点：
- 使用 `WithCallbacks` 注入进度回调，每完成一个 Chunk 更新任务进度
- 使用 `ProcessState` 存储术语表、累积摘要、当前章节索引
- 失败自动重试（指数退避），超过阈值标记为 FAILED_CHUNK，后续可人工修复

## 五、EPUB 格式处理策略

### 5.1 EPUB 结构保持

| 元素 | 处理策略 |
|------|---------|
| **OPF 元数据** | title/creator 追加中文译名，其余原样保留 |
| **目录 (TOC/NCX)** | 标题文本翻译，层级/顺序/链接 ID 完全一致 |
| **章节 HTML (XHTML)** | 仅翻译 `<p> <h1>~<h6> <li> <span>` 等文本节点，标签结构不动 |
| **图片/音频/字体** | 二进制资源原样复制，不做任何修改 |
| **CSS 样式** | 样式表原样保留，不修改 class/id |
| **脚注/尾注** | 作为独立文本块翻译，保持超链接锚点对应 |

### 5.2 HTML 文本分块算法

1. 解析 HTML DOM 树，按语义块（段落、标题、列表项）切分
2. 按 Token 预算（如每块 ~1500 tokens，留空间给 prompt+上下文）聚合语义块
3. 块边界只在语义块之间，不切断任何 `<p>` 或 `<li>`
4. 每块保留 HTML 片段上下文前后各 1 个标签，用于写回时定位

## 六、API 接口定义（初步）

### 6.1 创建翻译任务
```http
POST /api/v1/translate
Content-Type: multipart/form-data

Body:
  file:    <epub文件>
  source_lang:  auto | en | ja | fr ... (默认auto)
  target_lang:  zh-CN (默认)
  model:        doubao-pro-128k (默认)
  glossary:     <可选 术语表JSON>

Response: 202 Accepted
{
  "task_id": "uuid-string",
  "status": "QUEUED",
  "created_at": "2025-08-10T00:00:00Z"
}
```

### 6.2 查询任务状态
```http
GET /api/v1/tasks/:id

Response: 200 OK
{
  "task_id": "...",
  "status": "PARSING | TRANSLATING_CHUNK_12/87 | ASSEMBLING | COMPLETED | FAILED",
  "progress": 42.5,
  "total_chunks": 87,
  "translated_chunks": 37,
  "eta_seconds": 320,
  "error": null
}
```

### 6.3 下载翻译结果
```http
GET /api/v1/tasks/:id/download

Response: 200 OK
Content-Type: application/epub+zip
Content-Disposition: attachment; filename="book_title.zh-CN.epub"
```

## 八、MVP 范围与里程碑

### Phase 1：项目骨架初始化（已完成 - 本次任务）
- Go 模块初始化，Hertz + Eino 依赖引入
- 目录结构、配置、日志、路由骨架代码

- EPUB 2/3 解析：元数据、目录、章节 HTML 提取

- 断点续译：重启后从最后一个成功 Chunk 继续
- SSE/WebSocket 实时进度推送

### Phase 5：前后端对接 & 生产化
- 术语表上传、模型选择、翻译参数化
- 配置化多存储（S3/OSS）、多数据库（PG）

## 九、关键风险与应对

| 风险 | 影响 | 应对策略 |
|------|------|---------|
| 豆包模型翻译人名前后不一致 | 可读性严重下降 | 前置术语抽取 Agent + 强制术语表 Prompt 约束 + Review 节点二次校验 |
| 长篇小说上下文断裂 | 章节间情节不连贯 | 三重上下文机制 + 章节开头强制注入章节摘要 |
| HTML 结构损坏 | 翻译后 EPUB 无法阅读 | 仅翻译文本节点、保留 DOM 结构、生成后用 epubcheck 校验 |
| 单本书翻译耗时过长（10万词） | 用户体验差 | Chunk 级并发（5-10 worker）+ 实时进度 ETA 预估 + 任务队列 |
| LLM 流式输出中断 | 翻译失败率高 | Eino Callbacks 错误处理 + 指数退避重试 + 失败 Chunk 单独记录重试 |
